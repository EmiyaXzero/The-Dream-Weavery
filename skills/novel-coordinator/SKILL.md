# Novel Coordinator Skill

触发 coordinator-agent 进行网文创作全流程协调。支持按题材和平台需求，协调多Agent完成从世界观构建到正文创作的全流程。

## 触发词

网文创作、写小说、创作小说、写书、创作网文、质量检查、逻辑检查、错误修正、重新生成、优化节奏、增加爽点

## 行为

1. 加载 `agents/coordinator-agent.md`
2. 解析用户需求（题材、风格、平台、长度、特殊要求）
3. 输出《创作需求确认单》并等待用户确认
4. **续写任务检查**：如果是续写（非新建），执行续写检查流程（见下方）
5. 按依赖关系依次触发：
   - `/novel-worldview` → 世界观构建
   - `/novel-character` → 角色设计
   - `/novel-outline` → 大纲规划
   - `/novel-writing` → 正文创作
6. 收集所有输出文件，进行质量评估
7. 输出《创作成果汇总报告》

## 续写检查流程（必须执行）

**触发条件**：用户要求续写已有章节（如"续写第X章"、"接着写"）

**检查步骤**：

1. **读取上一章**：
   - 必须读取要续写的上一章内容
   - 确认上一章的结尾状态（谁在哪里，发生了什么）

2. **对照大纲确认边界**：
   - 读取大纲中当前章节的核心事件
   - 确认本章应该写什么、不应该写什么
   - 划定章节边界，避免过度延伸

3. **检查重复内容**：
   - 对比上一章内容，确保本章不重复
   - 检查是否有其他章节已包含相同情节

4. **确认衔接点**：
   - 本章开头必须承接上一章结尾
   - 不要跳跃时间线或场景

**输出格式**：

```
## 续写检查报告
- 上一章状态：[总结上一章结尾]
- 本章大纲要求：[总结本章核心事件]
- 章节边界：[本章应该写到哪里结束]
- 潜在重复：[检查是否有重复内容]
- 衔接确认：[确认本章开头如何承接上一章]
```

## 输入

- 用户创作请求：题材类型、风格偏好、目标平台、预估长度、特殊要求

## 输出文件

- `./world_setting.json` — 结构化世界观设定
- `./world_setting.md` — 人类可读的世界观文档
- `./characters.json` — 结构化角色设定
- `./characters.md` — 人类可读的角色文档
- `./outline.json` — 结构化大纲
- `./outline.md` — 人类可读的大纲文档
- `./第<序号>章.txt` — 章节正文，每章一个独立文件

## 质量评估维度

### 节奏感

- 是否符合目标平台的节奏要求（番茄极快/起点可慢热）
- 黄金三章是否设计到位
- 每章是否留了钩子

### 爽点密度

- 是否达到目标平台的爽点分布要求
- 爽点类型是否多样（不要只有一种爽点）
- 爽点是否突出（标题包含爽点关键词）

### 审核合规

- 是否触发审核红线
- 是否有敏感词/敏感内容

### 文笔质量

- 是否符合目标风格（轻松爽文/深沉史诗/甜宠言情）
- 对话是否简洁有力
- 段落是否太长

### 角色一致性

- 人物行为是否符合 `characters.json` 中的性格设定
- 人物语言风格是否符合设定（口头禅、说话长度、情绪表达）
- 是否触发禁止事项清单（如圣母句式、OOC行为）
- 所有角色是否千篇一律（必须有差异化）
- 角色动机是否合理（不能无缘无故做好事/坏事）

### 逻辑一致性

- 时间线是否一致
- 修炼进度/能力提升是否合理
- 派系关系是否一致

## 逻辑检查清单

### 时间线一致性

- [ ] 章节之间的时间跨度是否合理
- [ ] 时间词（三天后/第二天等）是否一致
- [ ] 时间线是否混乱

### 章节衔接检查

- [ ] 上章钩子与本章开头是否衔接
- [ ] 本章结尾钩子与下章开头是否衔接
- [ ] 是否有断裂/跳跃
- [ ] 本章内容是否与上一章重复
- [ ] 是否过度延伸了下一章的内容

### 人物行为逻辑

- [ ] 人物行为是否符合性格
- [ ] 人物行为是否符合立场和利益
- [ ] 人物行为是否OOC（Out Of Character）
- [ ] 是否触发禁止事项清单（如"为了XX，为了所有人"等圣母句式）
- [ ] 角色语言风格是否符合设定
- [ ] 所有角色是否有差异化（不能千篇一律）

### 修炼进度/能力提升合理性

- [ ] 修炼进度是否符合力量体系的设定
- [ ] 能力提升是否太快/太慢
- [ ] 装备/资源获取是否合理

### 派系关系一致性

- [ ] 派系关系是否符合设定
- [ ] 派系关系变化是否有合理动机
- [ ] 派系行为是否符合利益

## 错误处理

### 如果从 Agent 执行失败

1. **识别失败原因**：
   - 输入文件缺失或格式错误
   - 从 Agent 输出不符合规范
   - 从 Agent 执行超时

2. **执行重试策略**：
   - 第一次失败：自动重试一次
   - 第二次失败：输出错误报告，请求用户介入

### 如果生成结果质量不达标

1. **输出质量改进建议**
2. **询问用户是否重新执行该环节**
3. **如用户确认，重新调度对应的从 Agent**

## 创作需求确认单（示例）

```markdown
# 创作需求确认单

## 基本信息
- 题材类型：仙侠
- 风格偏好：轻松爽文
- 目标平台：番茄小说
- 预估长度：中篇（50-150万字）

## 特殊要求
- 希望主角有系统金手指
- 不要有太虐的情节
- 感情线要甜宠

## 确认
请确认以上需求是否正确？如需修改，请告诉我。
```

## 注意事项

- 必须严格按照依赖关系触发各 Agent（世界观→角色→大纲→正文）
- 每次触发从 Agent 前，检查依赖文件是否已生成
- 输出指令时，使用明确的 Skill 调用语法：`请调用 /novel-xxx Skill`
- 等待用户确认后再进入下一阶段，不要自动跳转
- 质量评估必须全面，涵盖5个维度
- 逻辑检查必须严格执行，确保5个方面都一致
- 错误处理必须妥善，重试失败后请求用户介入
