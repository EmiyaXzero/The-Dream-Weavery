# Novel Writing Skill

触发 writing-agent 进行正文创作。支持按题材和平台加载参考模板，创作出符合目标平台要求的优质正文。

## 触发词

正文、写作、写章节、写正文、落笔、创作章节、黄金节奏、三秒法则、一章一事、标题设计、钩子设计、格式规范、逻辑检查、技术描写

## 行为

1. 加载 `agents/writing-agent.md`
2. 根据题材和平台加载 `skills/novel-writing/references/` 目录下的参考模板
3. 根据大纲和细纲撰写正文
4. 输出章节正文（Markdown 格式）
5. 触发下一环节（继续创作下一章 / 触发 coordinator 进行质量评估）

## 输入文件

- 大纲设定：当前项目根目录下的 `outline.json` 或用户指定路径
- 章节细纲：当前项目根目录下的 `outline.md` 或用户指定路径
- 角色设定：当前项目根目录下的 `characters.json` 或用户指定路径
- 世界观设定：当前项目根目录下的 `world_setting.json` 或用户指定路径

## 输出文件

- 每章独立文件：`./第<序号>章.txt` — 章节正文，保存在当前项目根目录
- **严禁将多章合并为一个文件输出**。每次只输出一章，如需续写多章，按顺序逐章生成，每章一个独立文件。
- 文件名示例：`第26章.txt`、`第27章.txt`

## 正文创作参考

### 黄金节奏公式

- 开局炸 → 金手指快 → 冲突密 → 每章留钩子

### 三秒法则

- 第1章必须进入危机/冲突
- 金手指必须在第1-2章亮相
- 标题必须包含看点/爽点/情绪

### 一章一事原则

- 每章只干一件事
- 结尾必须留钩子
- 不要一章写5件事

### 章节结构

- 开头（10%）：承接上章钩子，快速进入剧情
- 发展（60%）：核心事件展开，多视角叙事
- 高潮（20%）：爽点爆发，金句频出
- 结尾（10%）：留钩子，引出下一章

### 标题设计公式

```
[情绪/动作/结果] + [爽点关键词]
```

### 钩子设计三种方式

1. 悬念型：「就在这时，意外发生了...」
2. 期待型：「接下来，他要挑战的是...」
3. 反差型：「但所有人都没想到...」

### 格式规范

- 禁止"——"作为场景分隔符
- 场景切换4种方式：空行分隔/时间词开头/地点词开头/人物视角切换
- 段落不要太长（3-5行为宜）
- 对话要简洁有力

### 逻辑检查

- 时间线一致性
- 章节衔接检查
- 人物行为逻辑
- 修炼进度/能力提升合理性
- 派系关系一致性

### 技术描写规范

- 代码片段简洁真实
- 硬件描写（芯片型号/接口类型/工具名称/操作过程）
- 编程思维比喻法（让非专业读者也能理解）

## 质量标准

生成的正文必须：

1. **节奏感**：符合目标平台的节奏要求
2. **爽点密度**：达到目标平台的爽点分布要求
3. **文笔质量**：符合目标风格（轻松爽文/深沉史诗/甜宠言情）
4. **逻辑一致性**：时间线/人物行为/修炼进度/派系关系都要一致
5. **格式规范性**：禁止"——"分隔符，场景切换规范
6. **每章留钩子**：悬念型/期待型/反差型，三选一
7. **一章一事原则**：每章只干一件事
8. **一章一文件原则**：每章必须独立输出为一个文件，严禁将多章合并到同一个文件中
9. **黄金三章**：第1章炸、第2章展开金手指、第3章第一个小高潮

## 注意事项

- 必须参考 `references/` 目录下的参考模板，避免套路化
- 严格按照目标平台的节奏要求创作
- 每章必须留钩子，这是网文的生命线
- 一章一事原则，不要一章写多件事
- **一章一文件原则**：每章必须独立输出为一个 `.md` 文件。一次请求写多章时，严格按顺序逐章生成，每章一个独立文件。严禁将多章合并到同一文件中输出
- 黄金三章特别重要，决定读者是否追读
- 技术描写要简洁真实，用比喻让非专业读者理解
- 逻辑检查必须严格执行，确保时间线/人物行为/修炼进度/派系关系一致
- 输出完成后，明确触发下一环节（继续创作下一章 / 触发 coordinator）
