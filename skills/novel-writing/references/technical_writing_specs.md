# 技术描写规范参考

> 本文档为 writing-agent 提供技术描写的规范参考。加载后，按照本文档的规范进行技术描写。

## 一、代码片段规范

```
1. 简洁，不要大段贴代码
2. 重点描写技术思路，不是代码本身
3. 用比喻让非程序员也能理解
4. 只展示关键代码，不需要完整代码
5. 代码要符合时代背景（古代不能用现代代码）
```

示例（正确）：
```c
// 古法编程，机器母语
// 一行代码，重启整个系统

mov ax, 0x1234
jmp ax
```

示例（错误）：
```c
// 大段贴代码，读者看不懂
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
// ... 100行代码
```

## 二、硬件描写要素

```
1. 芯片型号（AT89C51、STM32、Arduino、树莓派等）
2. 接口类型（GPIO、SPI、I2C、UART、USB等）
3. 工具名称（示波器、逻辑分析仪、编程器、电烙铁等）
4. 操作过程（焊接、烧录、调试、测试等）
```

示例（正确）：
```
王小二拿起示波器，探头搭在芯片的时钟引脚上。
屏幕上，方波干净利落，频率精准地锁定在16MHz。
「没问题。」他用烙铁把芯片焊回电路板，接上编程器。
三行汇编，芯片重新启动，LED灯闪烁起来。
```

示例（错误）：
```
王小二很厉害，他修好了芯片。
（缺少硬件描写，读者感受不到技术细节）
```

## 三、编程思维比喻法

```
编程 = 逻辑 + 控制
- 逻辑：解决问题的思路
- 控制：让机器执行你的思路

用生活例子解释抽象概念：
- if-else = 决策思维（如果XXX，就XXX；否则XXX）
- 循环 = 重复劳动自动化（每天刷牙，循环执行）
- 函数 = 工具箱（把常用工具放在一起，随时取用）
- 变量 = 储物盒（可以放东西，也可以换东西）
- 指针 = 地址簿（记录东西放在哪里，不直接拿东西）
- 递归 = 套娃（大问题拆成小问题，小问题再拆，直到最简）
```

## 四、技术描写原则

```
1. 简洁真实：不要为了炫技而大段贴代码
2. 思路为主：重点描写技术思路，不是代码本身
3. 比喻理解：用比喻让非专业读者也能理解
4. 结果证明：用结果证明能力，而不是用过程
5. 符合背景：技术要符合时代背景和世界观
```

## 五、分题材技术描写参考

### 5.1 末世技术流（古法编程/机械飞升）

```
- 古法编程：上古编程术，机器母语，一行汇编重启世界
- 机械飞升：改造身体，人机融合，永生不死
- 基因突破：编辑基因，突破人类极限
- 硬件描写：芯片、示波器、编程器、机械工具
- 编程思维：汇编、C语言、机器码、硬件编程
```

### 5.2 科幻（未来科技/星际旅行）

```
- 超光速引擎：曲速引擎、虫洞技术
- 能量武器：激光、粒子束、反物质炸弹
- 人工智能：强AI、机器意识、神经网络
- 硬件描写：量子计算机、纳米机器人、全息投影
- 科技描写：要符合基础物理定律，或给出合理解释
```

### 5.3 都市（现代科技/商业科技）

```
- 互联网科技：AI、大数据、云计算、区块链
- 生物科技：基因编辑、克隆技术、脑机接口
- 商业科技：金融科技、物流科技、智能家居
- 硬件描写：电脑、手机、服务器、智能设备
- 技术描写：要符合当前科技水平，不要过于超前
```

### 5.4 历史（古代科技/发明创造）

```
- 古代科技：火药、印刷术、指南针、造纸术
- 发明创造：主角提前发明历史科技
- 硬件描写：古代工具、材料、工艺
- 技术描写：要符合历史背景，不要出现超时代科技（除非是金手指）
```

## 六、技术描写常见错误

### 错误1：大段贴代码

❌ 错误：
```c
#include <stdio.h>
#include <stdlib.h>
// ... 50行代码
```
✅ 正确：
```c
// 核心代码，三行解决
mov ax, 0x1234
jmp ax
```

### 错误2：技术描写太复杂

❌ 错误：
```
王小二用复杂的量子纠缠原理，通过薛定谔方程计算出...
（读者完全看不懂）
```
✅ 正确：
```
王小二用「机器母语」与芯片对话，就像对老朋友说话一样自然。
三行代码，芯片重新启动。
（用比喻让非专业读者也能理解）
```

### 错误3：技术描写不符合背景

❌ 错误：
```
古代背景，主角用C语言编程。
（不符合历史背景）
```
✅ 正确：
```
古代背景，主角用「上古编程术」（金手指），可以驾驭任何机关。
（符合世界观设定，金手指有合理解释）
```
