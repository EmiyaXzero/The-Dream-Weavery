# 爽点矩阵模板参考

> 本文档为 outline-agent 提供各题材、各平台的爽点矩阵设计参考。加载后，按照本文档的模板规划爽点分布。

## 一、通用爽点矩阵模板

### 1.1 基础爽点类型

```
1. 技术碾压：主角用高超技术/能力碾压对手
2. 打脸：主角被打压后，反转打脸
3. 装逼：主角低调但实力强，被人轻视后惊艳全场
4. 收获：获得宝物/资源/传承/装备
5. 升级：能力/等级提升
6. 势力扩张：收小弟/建势力/统一区域
7. 感情：与女主/男主感情进展
8. 权谋：智斗/布局/破局
9. 战斗：战斗爽点，战斗胜利
10. 揭晓：身份揭晓/真相揭晓/伏笔回收
```

## 三、钩子设计模板

### 3.1 钩子类型

```
1. 悬念型：「就在这时，意外发生了...」/「他没想到，XXX」
2. 期待型：「接下来，他要挑战的是...」/「明天，就是XXX的日子」
3. 反差型：「但所有人都没想到...」/「表面上看XXX，实则XXX」
```

### 3.2 钩子设计原则

```
- 每章必须留钩子（一章一事原则+结尾留钩子）
- 钩子不能太弱（要让读者忍不住看下一章）
- 钩子不能太强（不能让读者觉得被耍了，要有实质性进展）
- 钩子要与下一章核心事件直接相关
```

### 3.3 黄金三章钩子设计（特别重要）

```
第1章结尾钩子：强悬念，让读者忍不住看第2章
  - 示例：「就在这时，他发现了XXX...」

第2章结尾钩子：期待型，铺垫第3章的打脸
  - 示例：「接下来，他要挑战的是...」

第3章结尾钩子：强悬念/期待型，引出下一个小目标
  - 示例：「但所有人都没想到，真正的XXX才刚刚开始...」
```

## 四、伏笔设计模板

### 4.1 伏笔类型

```
1. 明线：当前章节的主要剧情（读者能看到）
2. 暗线：埋下的伏笔（3-5章后回收）
3. 长线：贯穿全卷/全书的大伏笔（50-100章后回收）
```

### 4.2 伏笔设计原则

```
- 暗线伏笔：3-5章内必须回收，不能拖太久
- 长线伏笔：50-100章内必须回收，要有阶段性回收
- 伏笔埋设要自然，不能太明显（太明显读者一眼看穿，就没有惊喜了）
- 伏笔回收要有冲击力（最好是180度反转）
- 伏笔回收后要有合理解释（回头看发现铺垫充足，不是机械降神）
```

### 4.3 伏笔回收检查

```
- [ ] 暗线伏笔是否在3-5章内回收？
- [ ] 长线伏笔是否在50-100章内回收？
- [ ] 伏笔埋设是否自然（不突兀、不明显）？
- [ ] 伏笔回收是否有冲击力？
- [ ] 伏笔回收是否有合理解释（回头看铺垫充足）？
```

## 五、使用说明

1. **选择基础爽点矩阵**：参考 1.2 的通用爽点矩阵，根据平台调整
2. **选择题材爽点矩阵**：根据题材类型，选择 2.1-2.7 中的对应模板
3. **设计钩子**：每章必须留钩子，参考 3.1-3.3
4. **设计伏笔**：参考 4.1-4.3，规划伏笔埋设与回收
5. **规划爽点矩阵**：将爽点类型填入大纲的「爽点矩阵」字段
6. **检查爽点密度**：是否符合目标平台的要求

## 六、质量检查

- [ ] 爽点密度是否符合目标平台要求？
- [ ] 每章是否都有爽点（至少1个）？
- [ ] 每章是否都留了钩子？
- [ ] 钩子类型是否多样（悬念/期待/反差交替使用）？
- [ ] 伏笔埋设是否自然？
- [ ] 伏笔是否在合理章节内回收？
- [ ] 爽点类型是否多样，不要只有一种爽点？
